# MotionVLA Architecture

> This document describes the architecture as implemented in this repository and as defined in the paper *MotionVLA: Vision-Language-Action Model for Humanoid Motion*. There is no T5 decoder, no MoE, and no visual resampler — MotionVLA is a single-stream autoregressive Qwen3.5 model conditioned on text and a scene image, producing DSFT motion tokens.

---

## 1. DSFT — Dual-Stream Frequency-domain Tokenizer

### 1.1 Motivation

Human motion is **not spectrally homogeneous**. On HumanML3D and ViMoGen we measure the per-dimension low-frequency ratio (energy retained by the first 5 DCT coefficients):

- joint **positions / rotations** are dominated by low frequencies (~86–93% in the first 5 coefficients);
- joint **velocities** are markedly broadband (~37% in the first 5 coefficients).

A single shared codebook biases quantization toward pose statistics and under-represents high-frequency physical signals, which manifests as drift, foot sliding, and contact distortion in long-horizon generation.

### 1.2 Stream definition

Motion `M ∈ ℝ^{T × D}` is split into two streams along the feature dimension:

| Dataset | D | Base D_b | Phys D_p |
|---|---|---|---|
| HumanML3D | 263 | 190 | 73 |
| ViMoGen   | 276 | 201 | 75 |

For ViMoGen (276-dim, used by this codebase), the partition is:

```python
BASE_SLICES = [(0, 126), (126, 192), (258, 264), (270, 273)]  # 201 dims
PHYS_SLICES = [(192, 258), (264, 270), (273, 276)]            # 75  dims
```

i.e. Base = body_pose_6d + joints_xyz + root_orient_6d + root_trans; Phys = joints_vel + root_vel_6d + root_trans_vel.

### 1.3 Encoding pipeline

For each stream independently:

```
[T, D] --DCT(axis=0)--> [T, D] --truncate first K rows--> [K, D]
       --flatten + scale + integerize-->  ints
       --char-mapping + BPE encode-->     token IDs
```

Default truncation lengths:

- `K_base = 5` (Base stream is highly compressible)
- `K_phys = 25` (Phys stream needs a larger frequency budget; the paper's default ablation point)

Default vocabularies:

- `base_vocab = 4096`
- `phys_vocab = 2048`

Decoding inverts each step: BPE⁻¹ → reshape `[K, D]` → zero-pad to `[T, D]` → IDCT → recombine `[T, D_b]` and `[T, D_p]` along the feature dimension to recover `[T, D]`.

### 1.4 Reconstruction quality (HumanML3D)

| Method | Tok./Frame | rRMSE | MPJPE | rFID |
|---|---|---|---|---|
| Single-Stream DCT+BPE | 15.21 | 0.0164 | 0.0054 | 0.9461 |
| **DSFT (Kp=25)** | 11.24 | 0.0226 | 0.0093 | **0.1868** |

DSFT produces a more compact token sequence and a substantially lower reconstruction FID despite slightly higher pointwise error, indicating better distributional fidelity.

## 2. MotionVLA Backbone

### 2.1 Backbone choice

MotionVLA is built on a single autoregressive transformer — **Qwen3.5** (`--model_type qwen3_5` in ms-swift). The default configuration in the paper is **2B**; the backbone-scale ablation also covers 0.8B / 4B / 9B.

The backbone is **not** modified architecturally. We only:

1. Extend the vocabulary `V = V_LM + V_motion + 3` with new motion tokens and three structural markers `M_BOS`, `M_SEP`, `M_EOS`.
2. Use the standard `embed_tokens` / `lm_head` to handle motion tokens jointly with text tokens.
3. Apply LoRA adapters over `all-linear` modules during Phase 2.

There is **no** auxiliary T5 decoder, **no** MoE residual layer, and **no** custom visual resampler — image and text are encoded by Qwen's native multimodal stack via ms-swift.

### 2.2 Vocabulary layout (this codebase)

```
[ 0,            V_LM )                 ← original Qwen vocabulary
[ 248320,       248320 + 4096 )        ← Base motion tokens   (4096)
[ 252416,       252416 + 4096 )        ← Phys motion tokens   (4096; ≤2048 used by default DSFT)
  256512                                ← M_BOS
  256513                                ← M_SEP
  256514                                ← M_EOS
```

The motion vocabulary is exposed to ms-swift as `motion_tokens.txt` (generated by `training/prepare_swift_data.py`), and is added with `--new_special_tokens` so that ms-swift resizes embeddings consistently with the LoRA tuning path.

### 2.3 Unified token sequence

Each training sample serializes to a single sequence:

```
s = [ M_BOS, b_1, …, b_N, M_SEP, p_1, …, p_M, M_EOS ]
```

with Phys tokens placed after **all** Base tokens. Because Phys prediction conditions causally on the full Base context, this enforces a hierarchical *semantic-to-physical* generation order while preserving a vanilla autoregressive transformer.

### 2.4 Loss

Standard masked next-token cross-entropy:

```
L = CE( z + m, y )
```

where `z` is the output logits, `m` is a logit mask restricting prediction to motion tokens + structural markers, and `y` masks non-motion positions of the supervised target. This concentrates probability mass on the motion vocabulary only.

### 2.5 Phase-aware inference

To preserve the BASE → SEP → PHYS → EOS layout, decoding applies a phase-aware logit mask (Algorithm 1 in the paper):

- before `M_SEP`: only Base tokens or `M_SEP` are allowed;
- after  `M_SEP`: only Phys tokens or `M_EOS` are allowed.

After generation, Base and Phys tokens are decoded independently (BPE⁻¹ + IDCT) and recombined to reconstruct the full motion sequence.

## 3. Training Pipeline (ms-swift, two-phase)

### 3.1 Phase 1 — Embed warmup

Goal: bring the embeddings of newly added motion tokens to a reasonable initial scale **without** disturbing the rest of the backbone.

- Tuner: `full`
- Frozen: `model\.layers|model\.norm` (regex)
- Trainable: `embed_tokens`, `lm_head`
- LR: `1e-3`
- Steps: `500`
- Optimizer: `adafactor`

See [`training/train_swift_phase1.sh`](../training/train_swift_phase1.sh).

### 3.2 Phase 2 — LoRA SFT

Goal: fit the full motion-generation distribution efficiently.

- Tuner: `lora`, `rank=32`, `alpha=64`, `target_modules=all-linear`
- `modules_to_save`: `embed_tokens`, `lm_head` (preserve Phase 1 progress)
- LR: `2e-4`, cosine schedule, `warmup_ratio=0.03`
- Epochs: `3`
- Optimizer: `adamw_torch` (bfloat16, gradient checkpointing on)

See [`training/train_swift_phase2.sh`](../training/train_swift_phase2.sh) and [`training/train_swift_h100.sh`](../training/train_swift_h100.sh) for the combined H100 recipe.

## 5. Differences vs. earlier internal drafts

This document supersedes any earlier internal architecture notes that referenced:

- a separate **T5 decoder** for motion generation,
- a **MotionMoELoRALayer** / mixture-of-experts residual layer,
- a **VisualFeatureResampler** with explicit Conv1d/interpolation, or
- two-head (Base / Phys) prediction.

None of these components are part of the published MotionVLA. The shipped model is a single-backbone Qwen3.5 autoregressive predictor over the unified DSFT token sequence.
